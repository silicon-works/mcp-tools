# Integration Scenarios: shell-session
# Required: HTB VPN connection, target box with SSH access or exploitable services
# Suitable HTB Machines:
#   SSH-based:
#   - Lame (easy, SMB -> Samba 3.0.20 RCE gives root shell, SSH on port 22)
#   - Bashed (easy, webshell at /dev, can SSH after cred discovery)
#   - Shocker (easy, Shellshock -> www-data -> SSH with found creds)
#   - Irked (easy, UnrealIRCd backdoor -> user shell, SSH with found creds)
#   Reverse-shell-based:
#   - Lame (easy, Samba RCE -> reverse shell)
#   - Bashed (easy, phpbash -> Python reverse shell)
#   - Nibbles (easy, Nibbleblog upload -> reverse shell)
#   - Shocker (easy, Shellshock -> reverse shell)
#   - Precious (easy, Ruby PDFKit -> reverse shell)
# Prerequisites: VPN connected, target IP reachable, attacker IP known (tun0)
# Recommended FIRST box: Shocker (easy Linux, exercises SSH connect + exec + upload +
#   download lifecycle, has Shellshock for reverse shell scenarios, both www-data and
#   root available for privilege escalation testing)
# Run with: pytest tests/tools/test_shell_session.py --tool=shell-session -v
#
# Data source: Trajectory analysis of 411 real shell-session calls across 23 HTB
#   engagements.
#   Method calls: exec=346, ssh_connect=34, upload=18, close=8, download=4,
#     list_sessions=1, listen=0, shell_exec=0, upgrade_shell=0
#   Error data: 26 exec timeouts (8%), 14 ssh_connect timeouts (41% of connects),
#     14 session-not-found on exec, 12 permission denied, 7 command-not-found,
#     3 restricted shell (rbash), 1 invalid SSH key format
#   Duration stats: exec avg=10.4s p50=0.8s max=601s; ssh_connect avg=191s p50=10s
#     max=715s (timeout bug: paramiko timeout ignored, actual duration 10-20x requested)
#   Lifecycle patterns: Most engagements never call close (sessions left dangling),
#     one engagement had 4 reconnects across 80 calls, nohup/timeout wrapping used

Method: ssh_connect
Args: {host: <TARGET_THAT_HANGS>, username: "root", password: "test", timeout: 15}
Expected: success=false, error_class="timeout"
KNOWN BUG: Engagement data shows 14 ssh_connect calls where timeout=15-30s but actual
  duration was 585-715s. The asyncio.wait_for with overall_timeout=timeout+10 should
  catch this, but engagement data suggests it doesn't always work.
  Verify: actual duration should be close to (timeout + 10), NOT 10-20x timeout.

  but stall during SSH handshake trigger this. Reproduce with a host that has SSH
