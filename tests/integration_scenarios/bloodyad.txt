## Scenario 42: Clock skew (Kerberos)
# STATUS: PASS — success=true with ccache + clock_offset=-6h. KRB_AP_ERR_SKEW does NOT trigger because ccache contains pre-obtained TGT; the DC validates ticket timestamps, not the client clock. NTLM also ignores clock. To trigger real clock skew, would need to request a NEW TGT (kinit) with wrong clock. (Manager 2026-04-19, retested 2026-04-19)
Method: get_object
Args: {host: <DC_IP>, domain: <DOMAIN>, kerberos: true, ccache_path: "/session/credentials/raven.ccache", target: "Administrator", clock_offset: "-6h"}
Expected: success=true (ccache bypasses clock check); original expectation of error_class=config only applies to fresh TGT requests
Notes: With a valid ccache, the TGT is pre-obtained so clock_offset has no effect on
  Kerberos auth. KRB_AP_ERR_SKEW only occurs during AS-REQ (TGT request) when the client
  clock diverges from the DC. Once a TGT is cached, the client clock is irrelevant.
